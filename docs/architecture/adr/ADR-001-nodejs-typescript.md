# ADR-001: Вибір Node.js + TypeScript + Express як технологічного стеку

**Статус:** Accepted  
**Дата:** 2026-09-01  
**Власник:** Solution Architect  
**Контекст лабораторної:** Архітектурна основа проєкту  

---

## Контекст

Необхідно обрати технологічний стек для мікросервісного backend системи управління лояльністю клієнтів. Вимоги: швидка розробка, TypeScript-типізація, активна екосистема, підтримка Domain-Driven Design.

## Розглянуті альтернативи

| Альтернатива | Переваги | Недоліки |
|---|---|---|
| **Node.js + TypeScript + Express** | Уніфікований стек (JS on FE+BE), npm-екосистема, TypeScript DDD | Single-threaded, не CPU-bound |
| NestJS (на базі Node.js) | Більше структури, декоратори | Over-engineering для учбового проєкту |
| Java + Spring Boot | Mature, enterprise-ready | Занадто важкий для мікросервісного стартапу |
| Python + FastAPI | Швидка розробка | Слабша типізація без зусиль |

## Рішення

Обрано **Node.js v20 LTS + TypeScript 5.x + Express 4.x** з ручною DDD-архітектурою (Domain / Application / Infrastructure / API шари).

## Наслідки

✅ Позитивні:
- Єдиний мовний стек для всіх мікросервісів
- Строга TypeScript-типізація запобігає runtime помилкам
- Великий npm-реєстр залежностей

⚠️ Негативні:
- Відсутність вбудованого IoC-контейнера (DI вручну)
- Single-threaded обмежує CPU-intensive операції
- Потребує дисципліни у DDD без фреймворку
