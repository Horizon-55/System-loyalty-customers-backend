# ADR-008: SQALE Financial Model для оцінки технічного боргу

**Статус:** Accepted  
**Дата:** 2026-11-14  
**Власник:** QA Engineer / Solution Architect  
**Контекст лабораторної:** Лабораторна №9 (SQALE Financial Audit)  

---

## Контекст

Команда накопичила технічний борг через 8 лабораторних (рефакторинги, тимчасові рішення). Необхідна об'єктивна **фінансова оцінка** боргу та ROI рефакторингу для прийняття обґрунтованих архітектурних рішень.

## Рішення

Впроваджено **SQALE (Software Quality Assessment based on Lifecycle Expectations)** методологію через два рівні:

### 1. Forensic Audit через SonarQube Cloud REST API
Об'єкт аудиту: TypeORM (75,543 ncloc) — зразковий Open-Source TypeScript проєкт:
```
sqale_index = 12,551 хвилин боргу
sqale_rating = 1.0 (Grade A, TDD = 0.55%)
```

### 2. Software Economics NPV Симулятор (`scripts/financial-simulator.js`)

| Параметр | Формула | Значення |
|---|---|---|
| Principal (борг) | `sqale_index / 60 × $45 × 1.3` | $12,237.23 |
| Cost of Delay (місяць) | `ncloc / 100 × 1 год × $45 × 1.3` | $44,192.66 |
| Payback Period | NPV > 0 | **Місяць 1** |
| NPV(6 місяців) | Σ дисконтованих прибутків | +$243,880 |

**Висновок:** Рефакторинг окупається у перший місяць. ROI = **+1,893%** за 6 місяців.

## Наслідки

✅ Позитивні:
- Переводить якість коду у мову бізнесу (долари, місяці, ROI)
- Автоматизований через `scripts/financial-simulator.js`
- Аргументація для stakeholders: "Рефакторинг — це інвестиція, а не витрати"

⚠️ Негативні:
- Goodhart's Law: компанії можуть "маніпулювати" метриками SonarQube
- Cost of Delay — апроксимація (1 год/100 рядків), не точне вимірювання
