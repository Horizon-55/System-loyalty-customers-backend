## 1. Мета та інженерна проблема

### 1.1. Інженерна проблема (The "Noisy Neighbor" & Flaky Gate Problem)
У сучасних середовищах розробки та CI/CD пайплайнах (наприклад, shared GitHub Actions runners або спільні Kubernetes-ноди) тести продуктивності часто виконуються поруч із іншими ресурсомісткими процесами (компіляція великих проектів, генерація Docker-образів, сторонні cron-джобы).
Якщо метрики продуктивності (p95 Response Time, Error Rate) збираються в умовах неізольованого заліза, виникає феномен **Хибно-негативного спрацювання Quality Gate (False Negative FAIL)**:
> **Визначення False Negative:**  
> Quality Gate блокує збірку та маркує її як дефектну, хоча **жоден рядок програмного коду не містить регресії**. Причиною провалу є виключно нестабільність інфраструктури та нестача процесорного часу/пам'яті (CPU Throttling).

---

## 2. Методологія та сценарій проведення стрес-тесту

1. **Цільовий показник SLO (Service Level Objective):**
   - $\text{p95 Latency} \le 150.0\text{ ms}$ (95-й перцентиль часу відгуку).
   - $\text{Error Rate} < 1.0\%$ (Частка HTTP-помилок та таймаутів).
2. **Обсяг вибірки телеметрії:** $N = 1000$ HTTP-запитів із фіксацією логнормального розподілу затримок.
3. **Порівнювані середовища:**
   - **Тест 1 (Ізольоване середовище - Dedicated Baseline):** Виділені ресурси (2.0 vCPU, 2048 MB RAM), відсутність стороннього навантаження на хості.
   - **Тест 2 (Конкурентне шумне середовище - Noisy Contention):** Штучне обмеження процесорного квантування (CPU Throttling до 0.25 vCPU) та паралельний важкий процес, що створює конкуренцію за пам'ять та I/O.
4. **Засіб виконання:** Виконуваний автоматизований аудитор [`scripts/test-ops-stability.js`](file:///k:/Project%20Api/New%20Projects/System-loyalty-customers-backend/scripts/test-ops-stability.js).

## 5. Аналіз феномену False Negative та інженерні наслідки

1. **Чому впав Quality Gate?**
   Код застосунку в обох запусках був **абсолютно ідентичним**. Проте в Run 2 затримка $p_{95}$ підскочила з 57.3 мс до 637.7 мс, а Error Rate сягнув 1.8%, викликавши блокування пайплайну.
2. **Токсичність для інженерної команди:**
   - Інженери починають гарячковий дебаг "неіснуючої проблеми" у бізнес-коді, витрачаючи десятки годин.
   - Знижується довіра до системи CI/CD ("flaky pipeline"), через що девелопери вимагають відключити автоматичні Quality Gates.
3. **Висновок щодо агрегації (Stevens' Scales):**
   Середнє арифметичне ($204.6\text{ ms}$) повністю замаскувало факт того, що понад 5% користувачів чекали відповіді понад $637\text{ ms}$, а деякі — понад $2.5\text{ с}$. Використання саме $p_{95}$ перцентиля у відносній шкалі є життєво необхідним для Enterprise SLA.

## 6. Перелік впроваджених директив інженерного захисту

Для повної ліквідації впливу апаратного шуму в репозиторії впроваджено 3 рівні інфраструктурного захисту:

### Директива 1: Жорстка фіксація системних ресурсів у контейнерах
У [`api-gateway/docker-compose.yml`](file:///k:/Project%20Api/New%20Projects/System-loyalty-customers-backend/api-gateway/docker-compose.yml) та [`customer-service/src/docker-compose.yml`](file:///k:/Project%20Api/New%20Projects/System-loyalty-customers-backend/customer-service/src/docker-compose.yml) додано секції `deploy.resources`:
```yaml
deploy:
  resources:
    limits:
      cpus: '2.0'
      memory: 2048M
    reservations:
      cpus: '1.0'
      memory: 1024M
```
*Результат:* Запобігає starvation та гарантує, що контейнер отримує стабільний CPU quota без троттлінгу з боку сусідніх процесів.

### Директива 2: Детерміністична фіксація версій стеків (Package Pinning)
У [`package.json`](file:///k:/Project%20Api/New%20Projects/System-loyalty-customers-backend/package.json) та [`package-lock.json`](file:///k:/Project%20Api/New%20Projects/System-loyalty-customers-backend/package-lock.json) прибрано символи нечітких версій (`^` та `~`).
```json
"dependencies": {
    "typescript": "7.0.2"
}
```
*Результат:* Унеможливлює раптову зміну поведінки компілятора чи лінтера при автоматичному оновленні мінорних версій.

### Директива 3: Автоматична нормалізація закінчень рядків
У [`.gitattributes`](file:///k:/Project%20Api/New%20Projects/System-loyalty-customers-backend/.gitattributes):
```gitattributes
* text=auto eol=lf
*.ts text eol=lf
*.json text eol=lf
```
*Результат:* Гарантує байтову консистентність статичних метрик між Windows та Linux CI runners.
